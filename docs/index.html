0Before you start

Two things to confirm before installing anything.

  • You need a paid Claude account (Pro, Max, Team, or Enterprise). The free plan does not include Claude Code.
  • Open the Terminal app: press Cmd+Space, type Terminal, press Enter.

Confirm Homebrew is installed

Homebrew (brew) is the standard package manager for macOS. Check for it:

brew --version

If you see a version number like Homebrew 4.x.x, skip ahead to Step 1. If it says command not found, install Homebrew by pasting this in:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

The installer takes 5–10 minutes and may ask for your Mac password (normal — it's installing system tools). When it finishes, it prints two commands to add brew to your PATH. On Apple Silicon Macs (M1/M2/M3/M4) they look like this:

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
On an Intel Mac?

The path is /usr/local/bin/brew instead of /opt/homebrew/bin/brew. Always copy the exact commands the installer prints — they're customized for your machine.

Then quit Terminal completely (Cmd+Q), open a fresh window, and run brew --version again to confirm.

1Install the core tools

Run these one at a time. Each downloads and installs quietly.

brew install git
brew install node
brew install python@3.13
Notes

If brew says a package is already installed, that's fine — skip it. To update one, run brew upgrade <package>.

brew install node includes npm automatically.

When all three finish, quit Terminal completely (Cmd+Q) and open a fresh window. This is required — installers update your PATH, and an already-open terminal won't see the change.

2Verify the core tools

In the new window, run each of these. You should get a version number from every one.

git --version
node --version
npm --version
python3 --version
If git --version pops up an Xcode installer

On a fresh Mac, the first thing to ask for git can trigger a macOS dialog to install the Command Line Tools. Click Install and wait 5–10 minutes, then re-run git --version. (If you installed Git via brew in Step 1, you may not see this at all.)

If python --version says “command not found”

macOS only ships python3, not python. That's expected — use python3 everywhere. As long as python3 --version works, you're set.

3Install GitHub CLI & log in

This is the part that makes pushing painless. gh logs you into GitHub once and stores it securely in your Mac keychain — no tokens, no SSH keys.

Install it

brew install gh

Start the login

gh auth login

It asks a short series of questions. Answer them in this exact order — the highlighted choice is the one to pick (use the arrow keys, then press Enter):

? What account do you want to log into? GitHub.com ? What is your preferred protocol for Git operations? HTTPS ? Authenticate Git with your GitHub credentials? Yes ? How would you like to authenticate GitHub CLI? Login with a web browser

After the last choice, gh shows something like this:

! First copy your one-time code: A1B2-C3D4 Press Enter to open github.com in your browser...

Finish in the browser

  1. Copy the one-time code shown in your Terminal (e.g. A1B2-C3D4 — yours will be different).
  2. Press Enter. Your browser opens to GitHub's device-login page.
  3. If asked, sign in to GitHub with your username and password (and your 2-factor code, if you use one).
  4. Paste the one-time code into the box and click Continue.
  5. On the “Authorize GitHub CLI” screen, click the green Authorize button.
  6. The browser says you're all set — return to Terminal.

Back in Terminal you'll see a confirmation ending with ✓ Logged in as YOUR-USERNAME.

Why this matters

Because you chose HTTPS and Yes above, gh just configured Git to use your GitHub login automatically. From now on, git push simply works — you'll never be asked for a password or token again.

Confirm you're logged in

gh auth status

You should see ✓ Logged in to github.com account YOUR-USERNAME and a line noting the token is stored in keyring.

If the browser login gets stuck in a loop

Try a different browser for the sign-in (Safari, Chrome, Firefox), or temporarily ease strict tracker/cookie blocking. You can also re-run gh auth login and choose Paste an authentication token only if the browser flow truly won't work — but the browser flow is the recommended path.

4Put your project on GitHub & push

Now that gh is logged in, getting your folder onto GitHub is one command.

✨ Nina — the shortcut you’ll actually use

Here’s the part that makes everything below painless: now that gh is authenticated, you don’t have to type any of these Git commands yourself. Open the Claude desktop app, point it at your project folder, and just ask in plain English — for example:

“Commit all my changes and push them to GitHub.”

Claude will run the commands for you. (Purists will tell you to run them by hand so you understand each one — and that’s true — but the goal today is to get you shipping with zero friction. The manual versions are right below whenever you’re curious.)

In Terminal, go into your project folder (adjust the path to yours):

cd ~/Development/my-project

Then run:

gh repo create

Answer the prompts:

? What would you like to do? Push an existing local repository to GitHub ? Path to local repository . (just press Enter for the current folder) ? Repository name my-project ? Visibility Private (or Public, your call) ? Add a remote? Yes ? Would you like to push commits from the current branch? Yes

That creates the repo on GitHub, links it, and pushes your code — all at once. From here on, after you make changes, the everyday rhythm is just:

git add -A
git commit -m "describe what changed"
git push
Folder isn't a Git repo yet?

If gh repo create complains there's no repository, run git init and one commit first: git init && git add -A && git commit -m "first commit", then re-run gh repo create.

🔨 Fix a broken push

If a previous guide had you paste a token into the remote URL or set up an SSH key, reset to the clean setup here. You do not need a token or SSH key.

1. Make sure gh is installed and logged in

If you skipped Step 3, do it now — install and authenticate:

brew install gh
gh auth login

(Choose GitHub.com → HTTPS → Yes → Login with a web browser, exactly as in Step 3 above.) Then confirm:

gh auth status

2. Clean the token out of your remote URL

Go into your project folder and reset the remote to the plain HTTPS address — no token in it. Replace USERNAME and REPO with yours (copy the exact URL from the green Code button on your repo's GitHub page, HTTPS tab):

git remote set-url origin https://github.com/USERNAME/REPO.git

Check it looks right — clean, with no ghp_…@ in it:

git remote -v

3. Push

git push -u origin main

It should push without asking for a password. gh supplies your login from the keychain automatically. Done.

Why did another guide tell me to use a token or an SSH key?

Because both of those do work — they're just the older, more manual ways to prove to GitHub that you're you. When you ask a general AI assistant “how do I push to GitHub,” it tends to reach for the answer that has existed the longest and appears most often online:

  • Personal access token in the URL — the quickest thing to type into a chat, so it shows up constantly in old forum posts. But it bakes a secret password into your project, and it expires.
  • SSH keys — the traditional “proper” method, which is why an assistant defaults to it. But it's several fiddly steps (generate a key, add it to your Mac, paste it into GitHub's settings) that are easy to get wrong.

The assistant wasn't wrong, exactly — it just didn't know that GitHub's own tool, gh, was already installed on your machine. gh collapses all of that into one browser login and stores the credential safely in the macOS keychain. Same destination, far fewer ways to trip.

What was actually wrong with the token-in-URL approach?

Pasting a personal access token into the remote URL works for a moment, but the secret then sits in plain text inside your project's .git/config. It leaks if you ever share or back up the folder, and it stops working the day the token expires — sending you back to square one. gh stores the credential in the encrypted macOS keychain and refreshes it for you, so it just keeps working.
